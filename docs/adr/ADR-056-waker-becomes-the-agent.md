# ADR-056 — The waker becomes the agent: renaming the helper to what it is

- **Status**: Accepted
- **Date**: 2026-07-31
- **Related**: ADR-036 (the waker's birth), ADR-040/041 (observations), ADR-051→055 (the channel, host-ops, pipes, builds it now carries).

## Context

The helper container was born as the scale-to-zero waker (ADR-036): an HTTP
forwarder that wakes sleeping resources. Five ADRs later it terminates the
typed command channel, executes every Docker operation, the host file
primitives, the backup pipes and the BuildKit builds — the waking is one
module among many. Everything user-visible still called it "waker":
container name, CLI command, spec label, env vars — a name that misleads
operators about what the thing on their servers actually does.

## Decision

1. **The component is the `agent`; the waker is its module.** Renamed:
   container `akerdock-agent`, CLI `akerdock agent`, label
   `akerdock.agent_spec`, env `AKERDOCK_AGENT_DIR/ADDR`, package
   `internal/agent`, identifiers referring to the COMPONENT
   (`AgentEnsureCommand`, `AgentImage`, `agentScan`…). Identifiers naming
   the scale-to-zero forwarder subsystem keep "waker" — routes, activity,
   wake sets: that module wakes, its name is accurate.
2. **Migration without breakage** (agentSpec 9):
   - The renamed container carries `akerdock-waker` as a NETWORK ALIAS on
     user-defined networks: scale-to-zero route files generated before the
     rename resolve unchanged; new files target the new name. (The default
     bridge refuses aliases and hosts no route files — omitted there.)
   - The ensure's recreate branch removes any container still bearing the
     legacy name: a migrated server never runs two helpers.
   - The CLI keeps `waker` as an alias of `agent`: pre-rename containers
     exec `/akerdock waker` until their recreation.
   - The legacy env vars are read as fallbacks; the on-disk data directory
     stays `/var/lib/akerdock/waker` (routes and activity files survive the
     rename — it is the waker module's directory anyway).
3. Prose in earlier ADRs and the OpenAPI descriptions is left as written —
   accepted ADRs are immutable, and "waker" remains the correct name
   wherever the text describes the waking mechanic.

## Consequences

- One fleet-wide helper recreation (spec 9), through the reconciliation that
  every spec bump already rides.
- Operators see `akerdock-agent` in `docker ps`, which matches what the
  server page, the docs and the channel telemetry have been saying since
  ADR-051.
- The legacy alias can be dropped once every scale-to-zero route file has
  been regenerated by a redeploy — a later housekeeping change, not a
  decision.
