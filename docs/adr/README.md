# Architecture Decision Records (ADR)

Convention: one ADR per decision, numbered after the corresponding item of §27 of the [PRD](../PRD.md) through ADR-026; later ADRs are simply numbered sequentially. An accepted ADR is immutable: its substance is never modified again. A revision of a decision is made through a **new ADR** that explicitly states it supersedes the old one (the old one then moves to the status "Superseded by ADR-0XX").

| [ADR-065](ADR-065-idempotent-attach-token-claim.md) | An attach token is spent by the session it opens, not by the request that tries | Accepted | Revises the redeem clause of ADR-032 and of ADR-024's terminal in what "single use" counts, never in the property it protects: a mint authorizes at most one live authenticated session, held by one attacher, and the re-take window is the token's own 60 s TTL. "One request" was an exact proxy for that only while one request *was* one session — which stopped being true when ADR-064 put a retry ladder above the attach, so a rung that stepped down after the server had claimed burnt a token that never served a byte. The rule covers the two SQL-claimed attach paths — port-forward and terminal, which claims then dials SSH for a server shell exactly the same way; ingress stays out, its claim being a mutex over agent memory, a different atomicity argument and a different upgrade story. The 256-bit attach key moves from per-rung to per-mint (it is generated inside the ladder loop today, which makes every rung a different attacher); the claim stays exactly one statement with the idempotence in its `WHERE` plus two additive columns (`attach_key_hash`, `attach_seq`), `claimed_at`/`started_at` pinned to the first claim so a retry loop cannot buy duration. At most one live attach — supersession, the loser dying within one heartbeat on another replica. Load-bearing correction: an abandoned attach must stop finalizing the session, or `ended_at IS NULL` defeats the idempotent claim on its own. The WebSocket rung carries the key in a header, and a keyless claim stores server-generated random bytes so an N-1 client's token is not freely re-claimable for 60 s. |
| [ADR-066](ADR-066-attach-answers-before-it-dials.md) | The attach answers before it dials | Accepted | Revises the server-side timing of ADR-032's port-forward and of the terminal attach, along a line between what the control plane knows locally and what it must learn from two other machines: policy (token claim, attach key, protocol echo, store lookups, preview status, geometry, session bounds) keeps its place before the response head with its `409` and its prose; reachability (the agent `ContainerInspect` and the SSH handshake, or the terminal's `serverdial.Open` + `StartPTY` / exec-create + exec-attach) moves behind it. The two terminal shell kinds are not smoothed together: a container shell awaits no SSH client at all, so what the kinds share is the product of a network round trip, not a connection. The head stops being a bet on someone else's SSH latency — `servers.ssh_timeout_seconds` defaults to 30 s against a 5 s client open budget, a disagreement of a factor of six in favour of the side that is not waiting. The SSH client is dialled eagerly and awaited lazily: the resolution spends the seconds a human spends typing `psql`, not the ones they spend watching a connection; ownership stays with the session request through an idempotent promise, and the stream's await-plus-dial fits inside the existing `EgressDialTimeout`, so no client constant moves. An unreachable target is reported as the `502` a data stream already answers with, plus a session control frame and a new `target_unreachable` end reason (`disconnect` would send a developer to check their own network for a destroyed preview, and the terminal's current `revoked` claims an administrator acted when none did); a stream arriving mid-resolution **waits and is served** rather than being refused — the await-plus-dial lives inside the same `EgressDialTimeout`, so a stream that waits cannot hang longer than one that dials, and no new status code, error code or client behaviour is needed. The WebSocket rung keeps dialling before the upgrade — its open is bounded only by the command's context, so there is no bet to lose and it already renders the best diagnosis on the ladder. Also records that ADR-032's "existing pooled SSH connection" was never true: `serverdial.Open` handshakes per attach, which is why the defect reproduces; building a pool stays a separate decision. |
| [ADR-067](ADR-067-tunnels-are-scale-to-zero-citizens.md) | Tunnels and terminals are citizens of scale-to-zero | Accepted | Revises ADR-036 §2 on both its clauses — what *counts* as activity, and what may *start* a wake (the waker module stays the only thing that performs one) — and extends ADR-037 §3's `desired_status = running` gate from sleeping to waking. The two non-HTTP doors into a container, a tunnel dialling its IP over SSH and a terminal attaching a TTY on the agent channel, had no waker in their path: opening either against a sleeping resource failed with "the target container is not running", and neither could keep the resource it was attached to awake — a developer connected for 30 minutes read as perfect idleness and the scheduler stopped the container under them.
