# Architecture Decision Records (ADR)

Convention: one ADR per decision, numbered after the corresponding item of §27 of the [PRD](../PRD.md) through ADR-026; later ADRs are simply numbered sequentially. An accepted ADR is immutable: its substance is never modified again. A revision of a decision is made through a **new ADR** that explicitly states it supersedes the old one (the old one then moves to the status "Superseded by ADR-0XX").

| [ADR-058](ADR-058-session-role-inspection.md) | A session can inspect a role without a second account | Accepted | A browser session may carry a simulated role (system or custom, stored on the session row); its permissions become the INTERSECTION of what it holds with that role's, so nothing can be granted — root's wildcard included. | [ADR-060](ADR-060-dev-ingress-tunnels.md) | Ingress tunnels: a declared public URL relayed to a developer's machine | Proposed | The mirror of ADR-032/045: a declared `ingress_endpoints` resource (stable FQDN registered in `domains`, ingress server, no random per-session hostnames) whose Traefik router and certificate are pre-provisioned at declaration, pointing at the agent's HTTP front (offline page when unattached); the CLI attaches outbound over wss on the endpoint's own FQDN (`akerdock-ingress-v1`, single-use `akdi_` token minted by the control plane, redeemed agent-side) and visitor connections are byte-spliced to the laptop — the control plane never carries a visitor byte (INV-007). | [ADR-061](ADR-061-ingress-http3-http2-websocket-fallback.md) | Ingress transport: HTTP/3, then HTTP/2, then WebSocket | Proposed | Revises ADR-060's laptop transport: independent full-duplex HTTP streams, strict HTTP/3 → HTTP/2 → WebSocket fallback with four persistent connections per HTTP transport (a transport must be able to carry what admission accepts: a QUIC peer advertises ~100 streams, and one connection would stall past 99 rather than refuse), per-session keep-alive, bounded compatibility flow control, HTTP/3 on the managed Traefik entrypoint, and transport/latency/throughput metrics. |
| [ADR-062](ADR-062-proxy-convergence-and-lockout-recovery.md) | The managed proxy converges to its intent, and never traps the operator | Proposed | Extends ADR-009's drift reconciliation from the dynamic files to the container that reads them: when the intent is `running`, an absent proxy is re-bootstrapped and a stopped one started, with exponential backoff and a flip to `unhealthy` past a threshold — an explicit `stopped` is still never repaired. Stopping or removing the proxy that routes the instance FQDN (reserved `00-control-plane` scope) requires an explicit acknowledgement stating the consequence and the recovery command, because passkey and OIDC sign-in are bound to that origin and an SSH port-forward authenticates nobody. `akerdock proxy repair`, run on the host with the instance's own configuration, re-renders the static config and converges the container without the dashboard. |
| [ADR-063](ADR-063-ingress-attach-h2c-backend-hop.md) | The ingress attach hop speaks h2c to the agent; the visitor hop cannot | Proposed | Extends ADR-061 to the last hop of the chain: Traefik terminated the laptop's HTTP/2 or HTTP/3 and re-serialized the tunnel into one HTTP/1.1 backend connection per relayed stream. The reserved attach router (`/.akerdock/ingress`) now gets its own IR-generated service over `h2c://akerdock-agent:8080`, so the control stream and every data stream stay multiplexed with native full duplex and per-stream flow control; the agent serves cleartext HTTP/2 alongside HTTP/1.1 on its single internal port, never sets `ReadTimeout` (Go arms it as a per-stream deadline on the HTTP/2 request body — the 60 s cut ADR-061 removed at the Traefik level) and advertises 1024 concurrent streams, above the tunnel's 128 active + 512 queued admission bound. The visitor hop stays HTTP/1.1 by necessity, not by preference: `Connection`/`Upgrade` are invalid HTTP/2 request headers (RFC 7540 §8.1.2.2) and nothing in the chain performs the RFC 8441 translation, so an h2c visitor hop would break every relayed WebSocket. |
| [ADR-064](ADR-064-one-transport-ladder-for-every-cli-tunnel.md) | One transport ladder for every CLI-to-server tunnel | Proposed | Generalises ADR-061's ladder (probe → HTTP/3 → HTTP/2 → WebSocket, with per-process probe cooldown, failure budget and policy-versus-transport classification) from the ingress tunnel to port-forward, bastion and terminal — three families that otherwise pay for each transport defect once each, as a single day's three ingress fixes showed. Wire identifiers stay parameterised per access path (ADR-027), so no token crosses paths; choreography stays per path (`HTTPOrigin` remains ingress-only, since only ingress has the server asking the client to open). Revises ADR-024's "WebSocket reserved for the terminal" clause — WebSocket stays the bottom rung, the terminal gains QUIC connection migration. Endpoints deliberately unchanged: this decides how bytes are carried, not who terminates them. |
