# Architecture Decision Records (ADR)

Convention : un ADR par décision, numéroté d'après le point correspondant du §27 du [PRD](../PRD.md). Un ADR accepté est immuable : on ne le modifie plus sur le fond. Une révision de décision se fait par un **nouvel ADR** qui indique explicitement qu'il supersede l'ancien (l'ancien passe alors au statut « Remplacé par ADR-0XX »).

| N° | Titre | Statut | Résumé |
|---|---|---|---|
| [ADR-001](ADR-001-transport-ssh-puis-agent.md) | Transport de contrôle : SSH d'abord, agent sortant en cible, ports configurables | Accepté | SSH pour la parité, agent sortant comme cible ; proxy 80/443 configurable par serveur, control plane sur un seul port. |
| [ADR-002](ADR-002-queue-postgresql.md) | Queue durable PostgreSQL, sans bus externe | Accepté | La queue de jobs vit dans PostgreSQL (leases, outbox) ; interface abstraite mais aucun Redis/NATS planifié. |
| [ADR-003](ADR-003-secrets-chiffrement-enveloppe.md) | Secrets : chiffrement enveloppe AEAD en base | Accepté | AES-256-GCM dans PostgreSQL, clé maître externe, rotation versionnée ; interface `SecretStore` interne, Vault/KMS seulement sur demande validée. |
| [ADR-004](ADR-004-runtime-docker-standalone.md) | Runtime : Docker standalone confirmé, Kubernetes écarté | Accepté | Engine/Compose/BuildKit ; Kubernetes rejeté (même embarqué), Swarm non réimplémenté ; réévaluation seulement sur besoin validé via l'adaptateur runtime. |
| [ADR-005](ADR-005-builds-buildkit-rootless-code-non-fiable.md) | Builds : BuildKit du serveur en P0/P1, rootless obligatoire pour le code non fiable | Accepté | Parité d'abord ; builders BuildKit rootless dédiés au plus tard avec les previews de forks approuvés ; contrat d'adaptateur build écrit dès P0. |
| [ADR-006](ADR-006-rollback-digest-oci-registry.md) | Rollback : digest OCI en registry, rétention locale protégée sinon | Accepté | Avec registry : push et rollback par digest OCI ; sans : N dernières images locales protégées du cleanup (INV-015). |
| [ADR-007](ADR-007-rbac-fin-projet-environnement.md) | RBAC fin par projet et par environnement | Accepté | Rôles/permissions au grain projet et environnement, au-delà d'admin/member ; détail dans la matrice RBAC (§29.7). |
| [ADR-008](ADR-008-observabilite-otlp-partout.md) | Observabilité : OTLP partout, exposition Prometheus | Accepté | Agent, control plane et workers émettent métriques/traces/logs en OpenTelemetry ; aucun protocole propriétaire. |
| [ADR-009](ADR-009-proxy-representation-intermediaire.md) | Proxy : représentation intermédiaire commune, Traefik P0, Caddy P2 | Accepté | IR commune + labels de parité + fixtures de conformité partagées dès P0 ; Traefik seul en P0, Caddy en P2. |
| [ADR-010](ADR-010-catalogue-templates-depots-git.md) | Catalogue one-click : dépôt projet signé + dépôts utilisateur | Accepté | Catalogue officiel versionné/validé/signé, indépendant du binaire ; chaque team peut brancher ses propres repos Git de templates. |
| [ADR-011](ADR-011-previews-enrichies-des-la-livraison.md) | Previews de PR enrichies dès la livraison | Accepté | Tout le §20.4 est prioritaire (compose éphémère, TTL/plafonds, protection par défaut, checks, forks approuvés) ; contrôles de déclenchement opt-in par application. |
| [ADR-012](ADR-012-config-as-code-yaml-terraform.md) | Config as code : export YAML + apply idempotent + Terraform officiel | Accepté | Export YAML stable, apply avec dry-run/diff, secrets référencés ; provider Terraform/OpenTofu officiel sur l'API. |
| [ADR-013](ADR-013-adoption-ressources-existantes.md) | Adoption de ressources existantes | Accepté | Adoption sans redéploiement, prévisualisée et réversible, des containers/stacks non gérés (workflow §20.7). |
| [ADR-014](ADR-014-backups-volumes-moteurs-restore-drills.md) | Backups : volumes, Redis/ClickHouse, restore drills | Accepté | Backup de volumes chiffré/dédupliqué, moteurs Redis et ClickHouse, drills de restauration automatiques avec alerte. |
| [ADR-015](ADR-015-fiabilite-compose-by-design.md) | Fiabilité compose « by design » | Accepté | Zero-downtime par service pour les stacks compose et resource limits réellement appliquées (les deux pièges structurels du §15, traités dès la conception). |
| [ADR-016](ADR-016-deploiement-coordonne-environnement.md) | Déploiement coordonné d'un environnement | Accepté | Environnement déployable comme une unité : graphe de dépendances, hooks de migration avant bascule, mode atomique par niveau, rollback auto opt-in. |
| [ADR-017](ADR-017-uptime-monitoring-integre.md) | Uptime monitoring intégré, sans APM | Accepté | Checks HTTP/TCP exécutés hors du workload, alerting via les canaux existants, historique par ressource ; périmètre borné au up/down et à la latence. |
| [ADR-018](ADR-018-deploiement-local-akerdock-up.md) | Déploiement depuis le poste : `akerdock up` | Accepté | La CLI peut pousser un contexte local (prototypage) ; marqué dans l'historique (digest de contexte, pas de SHA), jamais d'auto-deploy. |
| [ADR-019](ADR-019-notifications-routage-agregation.md) | Notifications : routage, agrégation, heures calmes | Accepté | Règles par projet/environnement/sévérité, débounce du flapping, heures calmes et résumé différé du non-critique. |
| [ADR-020](ADR-020-licence-apache-2-0.md) | Licence du projet : Apache 2.0 | Accepté | Même licence que la référence, clause brevets incluse ; le risque de fork cloud par un tiers est accepté. |
| [ADR-021](ADR-021-distribution-compose-deux-services.md) | Distribution : docker-compose minimal à 2 services | Accepté | Image AkerDock (Go statique, distroless, modes all-in-one/api/worker) + PostgreSQL ; un port exposé, upgrade par tag. |
| [ADR-022](ADR-022-variables-prefixe-akerdock-sans-alias.md) | Variables prédéfinies : `AKERDOCK_*` sans alias | Accepté | Préfixe propre, aucun alias sous une autre marque (templates tiers réécrits à l'import) ; syntaxe `SERVICE_<TYPE>_<ID>` conservée. |
| [ADR-023](ADR-023-migration-par-adoption-generique.md) | Migration par l'adoption générique | Accepté | Pas d'assistant d'import propriétaire : l'adoption (§20.7) prend le contrôle des objets Docker standards déjà en place, quelle qu'en soit l'origine ; réévaluable sur demande avérée. |
| [ADR-024](ADR-024-temps-reel-sse-websocket-terminal.md) | Temps réel : SSE, WebSocket réservé au terminal | Accepté | SSE avec reprise `Last-Event-ID` pour logs/statuts/jobs ; WebSocket uniquement pour le terminal ; tout sur le port unique. |
| [ADR-025](ADR-025-socle-go-pgx-sqlc-chi-oapi-codegen.md) | Socle Go/API : pgx + sqlc, chi + oapi-codegen spec-first | Accepté | SQL explicite typé à la compilation, migrations versionnées ; handlers Go et client TypeScript générés du même artefact OpenAPI. |
| [ADR-026](ADR-026-e2e-docker-in-docker.md) | Tests E2E : Docker-in-Docker uniquement | Accepté, cadence révisée par ADR-028 | Serveurs simulés en containers ; systemd, reboots, firewalls, disques pleins et ARM64 hors automatisation (risque accepté). |
| [ADR-027](ADR-027-retrait-tunnels-provisioning-patching.md) | Retrait : tunnels Cloudflare, provisioning cloud, server patching | Accepté | Les trois capacités P3 sortent du périmètre (réévaluable sur demande avérée) ; DNS-01 et S3 (Cloudflare/Hetzner) non concernés ; `cloud_credentials` reste — elle porte les credentials DNS-01. |
| [ADR-028](ADR-028-pyramide-tests-un-seul-e2e.md) | Pyramide de tests : un seul parcours E2E | Accepté | Un seul parcours DinD après fusion et avant release ; PR bloquées par les tests unitaires/module ; aucun catalogue nightly. Révise la cadence et le volume de l'ADR-026. |
| [ADR-029](ADR-029-seed-preview-clone-volume.md) | Seed des previews de PR par clone de volume | Accepté | `x-akerdock.preview_seed: clone` copie le volume de production dans la preview (volume vide uniquement) ; compromis de cohérence documenté. |
| [ADR-030](ADR-030-preview-sso-forward-auth.md) | Protection des previews par SSO AkerDock (forward-auth) | Accepté | Mode `preview_protection: sso` : forwardAuth vers le control plane, cookie de preview dédié, session AkerDock (toute méthode) fait foi ; Clear-Site-Data rejeté. |
| [ADR-031](ADR-031-login-cli-poll-code-pkce.md) | Authentification du CLI : poll + code + PKCE | Accepté | `login` navigateur sans ouvrir de port (SSO compris), token `akd_` normal ; invariant transport 80/443/manager-only/proxy-safe. |
| [ADR-032](ADR-032-tunnel-tcp-cli-websocket.md) | Tunnel TCP du CLI : WebSocket multiplexée | Accepté | Étend ADR-024 (WS = flux bidirectionnels) ; mint/redeem, une WS multiplexée par session, canal SSH par stream ; frontière ressource-pas-port. |
| [ADR-033](ADR-033-cli-cobra-migration-run-modes.md) | Passage à Cobra : modes serveur en sous-commandes | Accepté | Full-Cobra dans le binaire unique ; `serve …` remplace les args positionnels, repli déprécié le temps d'une version. |
| [ADR-034](ADR-034-metriques-live-a-la-demande.md) | Métriques live à la demande via SSH | Accepté | Complète ADR-008 : jauges CPU/RAM par service via `docker stats --no-stream` sur la connexion runtime, sans persistance ; l'historique reste OTLP externe. |
